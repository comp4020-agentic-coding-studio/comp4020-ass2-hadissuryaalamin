## Produce and fallback tier

Fallback tier **(a)**: substitute a comparable vegetable. Wikimedia
Commons has no photograph of pak choy (the user's original yellowing-
greens example) in a spoiled or declining state — confirmed by browsing
`Category:Brassica rapa subsp. chinensis` (living-plant and pest-damage
photos only) and several full-text search variants (all off-subject,
mostly scanned documents). `Category:Spoiled food` surfaced a matched
pair of onion cross-section photographs instead:

- `onion-fresh-cross-section.jpg` — File:White onion cross section.jpg,
  CC BY-SA 3.0, Amada44. Pale, translucent cross-section.
- `onion-declining-cross-section.jpg` — File:Rotten onion.jpg, CC BY-SA
  4.0, Tiia Monto. Same cut, centre browned and collapsed, outer rings
  still pale.

Both checked before use (real camera EXIF, plausible dates, no AI
generation tells), both on-white-background cross-section shots so the
pairing reads as deliberately comparable rather than mismatched photos.
This also lines up more precisely with the deck's own existing colour
claim ("discoloured at cut edges is already declining") than an
exterior-yellowing photo would have — a cut-face comparison, not a whole-
vegetable exterior one.

Firmness is named in the caption ("softened") alongside colour, since
the same cross-section shows both changing together; the pairing did not
extend to a third, separate firmness-only illustration.

## CSS fix found during verification

The initial `.compare figure img { width: 100% }` rule let the two
photos (one portrait cross-section) render tall enough that the slide's
total content height reached 897px against the deck's fixed 720px
canvas — the second figure's two-line caption was pushed past the
canvas bottom and was invisible or clipped depending on viewport height.
Fixed in `src/decks/theme.css` by capping images at `max-height: 19rem`
(auto width, `object-fit` not needed since both source images are
already tightly cropped) rather than stretching to the container width.
Re-measured via a Playwright script against the running dev server:
slide content now measures exactly 720px, both figcaptions sit well
inside the section bounds.
