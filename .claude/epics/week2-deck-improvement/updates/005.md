# 005 — Nutrition: reconcile with the calculator, then deepen

## FDC-ID reconciliation

Both FDC IDs are real, distinct foods — the deck's equality claim was the
only false part, not either figure:

- **170032, "Potatoes, raw, skin"** — 58 kcal, 0.10 g fat, 2.57 g protein
  per 100 g. This is the potato *skin alone*.
- **170026, "Potatoes, flesh and skin, raw"** — 77 kcal, 0.10 g fat,
  2.05 g protein per 100 g. This is the *whole potato* (flesh + skin),
  and it is what `src/data/macro/week-02.ts` already uses.

Verified directly against the USDA FoodData Central API
(`api.nal.usda.gov/fdc/v1/food/<id>`) for both IDs before making any
change. Applied the epic's default resolution: aligned the deck table
(and the lecture's matching table) to the calculator's five ingredients
— dropping the skin-only row rather than keeping two potato entries side
by side — and rewrote every sentence that had claimed the deck and
calculator figures were "exactly" the same, since the deck no longer
carries a different potato entry at all.

## Deepening: vegetables and nutrient column added

Added three vegetables, chosen to give each of the deck's own four
families ("Families, briefly" slide) two entries instead of one, and
one further nutrient column (fibre, per 100 g raw, since USDA carried it
consistently for every candidate — vitamin C and total sugars were also
checked and are consistent, fibre was picked to keep the column count
minimal):

| Vegetable | FDC ID | kcal | Fat (g) | Protein (g) | Fibre (g) |
|---|---|---|---|---|---|
| Garlic, raw | 169230 | 149 | 0.50 | 6.36 | 2.10 |
| Cauliflower, raw | 169986 | 25 | 0.28 | 1.92 | 2.00 |
| Lettuce, cos/romaine, raw | 169247 | 17 | 0.30 | 1.23 | 2.10 |

Every figure (new and pre-existing) was cross-checked against at least
one independent USDA-data mirror in addition to the FDC API response
(garlic and lettuce/cauliflower each checked against a second source;
figures matched exactly). The table is now 8 rows across 4 families
(roots/tubers, alliums, leafy greens, brassicas), 5 nutrient columns,
each with its FDC ID — deck, lecture table and lecture `links:`
frontmatter all agree.

## Calculator (`src/data/macro/week-02.ts`) — left unchanged

Chose **not** to extend the calculator to the new three vegetables. The
epic's default resolution only required reconciling the existing
mismatch, not growing the interactive tool; `types.ts`'s own comment
("4-6 ingredients a student can select") argues for restraint; and no
spec test constrains ingredient count either way. The deck/lecture prose
now says plainly that garlic, lettuce and cauliflower are not yet
selectable in the calculator, so the claim stays true. Because the file
was not touched, the consuming component
(`src/components/MacroCalculator.astro`, rendered from
`src/content/sessions/02-vegetables.mdx`'s tutorial) needed no
verification beyond confirming `pnpm check`'s production build still
compiles it — it does, and its behaviour is unchanged from before this
task.

## Layout: the widened table did not fit as one slide

First attempt put all 8 rows (6 columns) on the deck's existing single
nutrition-table slide. Screenshotting it in the dev server showed the
last row (Cauliflower) cut off against Reveal's fixed 1280×720 canvas —
a real overflow, not a false alarm. Fixed by splitting into two slides
grouped by family pair (`## Roots, tubers and alliums, per 100 g` /
`## Leafy greens and brassicas, per 100 g`), 4 rows each, matching how
the rest of this deck already prefers several short slides over one
dense one (e.g. the five cut-shape slides from task 002). Re-screenshot
confirmed both fit with comfortable margin.
