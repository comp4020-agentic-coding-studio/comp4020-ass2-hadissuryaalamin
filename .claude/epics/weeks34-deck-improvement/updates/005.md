# Task 005 — week 3 nutrition reconcile and deepen: progress log

## What was found before anything was written

Every figure was verified against USDA FoodData Central (via the FDC API,
`https://api.nal.usda.gov/fdc/v1/food/<id>`, proxied through `r.jina.ai`
since the API's own DEMO_KEY was rate-limited and `fdc.nal.usda.gov`'s
food-details pages are a client-rendered SPA that 404s on a bare fetch)
before recording anything. This turned up two pre-existing errors in
`src/data/macro/week-03.ts`, already in the repo before this task started:

- The cod entry's `fdcId: 172904` does not resolve to cod — it resolves to
  **"Soup, bean with pork, canned, prepared with equal volume water."**
  The correct FDC ID for "Fish, cod, Atlantic, raw" (SR Legacy) is
  **171955**. Its protein figure was also off (18.4 g recorded vs 17.81 g
  actual — calories 82 kcal and fat 0.67 g happened to already be right).
- Duck's calorie figure was recorded as 132 kcal; the real FDC 172410
  entry is **135 kcal** (fat 5.95 g and protein 18.28 g were already
  correct).

Fixed both in `week-03.ts` as a standalone commit before touching the
deck or lecture, so the figures this task copies into graded/visible
content are copied from a corrected source, and so the calculator's own
citation link (`MacroCalculator.astro` builds
`https://fdc.nal.usda.gov/food-details/${fdcId}/nutrients` straight from
this file) actually resolves to the food it names. This is not
"extending" the ingredient count (still four items, `types.ts` untouched)
— it's a correction the task's own verification mandate surfaced.
Consuming end confirmed still working: `MacroCalculator.astro` renders
off the same `MacroIngredient` shape, no schema change, and the lecture
page's rendered cod/duck figures were spot-checked against the corrected
file (see verification below).
