## Component API

```astro
<StorageCalculator data={week05Storage} />
<!-- optional: id="custom-id" if more than one calculator lands on one page -->
```

Props (`src/components/StorageCalculator.astro`):

- `data: StorageDataset` (required) — one week's dataset, imported from `src/data/storage/week-NN.ts`.
- `id?: string` — DOM id prefix, defaults to `storage-calculator-${data.week}`.

`StorageDataset` shape (`src/data/storage/types.ts`):

```ts
interface StorageItem {
  id: string;
  label: string;        // shown in the <select>
  condition: string;    // storage condition, stated with units
  durationHours: number; // safe-storage duration from prep time
  note?: string;         // optional caveat, shown with the result
}
interface StorageSource { label: string; url: string; }
interface StorageDataset { week: number; title: string; items: StorageItem[]; sources: StorageSource[]; }
```

## Behaviour

Native `<select>` (ingredient/dish type) + native `<input type="datetime-local">`
(prep time) + submit button. On submit, client-side JS (plain `<script>`,
no framework — `astro.config.ts` has no React/Vue/Svelte integration to
prefer) reads `durationHours` off the selected `<option>`'s data attribute,
adds it to the parsed prep time, and writes the formatted safe-until
date/time plus duration and any `note` into a `role="status"
aria-live="polite"` result paragraph. Sources are rendered as a linked list
below the form, satisfying "citation in the data file, not just prose."
Multiple instances on one page are supported (`querySelectorAll` +
per-instance init) though only one is expected per tutorial page.

Accessibility: every input has a matching `<label for>`, focus-visible
outlines are set explicitly (not suppressed), no state is conveyed by
colour alone, and native `datetime-local` is used instead of a custom
picker as the task specified.

Spot-checked arithmetic: week 10, "Raw poultry, refrigerated at or below
4°C" (durationHours 48) with a prep time of `2027-04-26T09:00` computes a
safe-until of `2027-04-28T09:00` — two days later, matching the item's
stated condition.

## Data sourcing

All three weeks cite the same USDA FSIS source family already used in
`src/content/sessions/10-food-safety-and-the-cold-chain.md` and
`11-first-heat.md`:

- USDA FSIS, "'Danger Zone' (40°F - 140°F)" — the 2-hour/1-hour holding-time
  rule, reused verbatim (same as session 10).
- USDA FSIS, "Refrigeration and Food Safety" — general refrigeration
  guidance already cited in session 10.
- USDA FSIS, "Leftovers and Food Safety" — new page within the same
  fsis.usda.gov family, used for cooked/held preparations (stocks, sauces,
  cooked leftovers): its general 3-to-4-day refrigerated window.

Per-week data:

- **Week 5 (aromatics and oil):** danger-zone holding items for chopped/
  crushed alliums at normal (2 h) and hot (1 h) ambient temperature, plus
  refrigerated alliums and refrigerated prepared leaf herbs at 72 h (3
  days). FSIS publishes no allium- or herb-specific refrigerated figure, so
  the refrigerated items apply FSIS's general 3-to-4-day window for cut/
  prepared perishable food at its conservative (shorter) end — stated
  explicitly in each item's `note` rather than presented as an
  allium-specific chart line. I deliberately did not include a
  garlic-in-oil/botulism item: secondary sources attribute conflicting day
  counts (4 vs 7 days) to "USDA guidance" and I could not verify either
  figure against primary FSIS text (fsis.usda.gov blocks the fetch tool
  with 403s), so per the course's own "if a figure cannot be sourced, teach
  the concept without the number" rule, it's left out rather than risk an
  unverifiable safety-critical number.
- **Week 8 (guest lecture, time management under service):** danger-zone
  holding items (2 h / 1 h) for portioned/blanched/staged items awaiting
  service, plus stock and sauce (96 h / 4 days, "Leftovers and Food
  Safety") and blanched/portioned vegetables (72 h / 3 days, same
  conservative general-window reasoning as week 5).
- **Week 10 (food safety and the cold chain):** restates the session's own
  cited figures as calculator data — raw poultry and raw ground meat at 48
  h (session 10: "one to two days," upper bound), raw steaks/chops/roasts
  at 120 h (session 10: "three to five days," upper bound) — plus cooked
  leftovers at 96 h ("Leftovers and Food Safety") and the danger-zone
  holding items. Cut fruit is deliberately excluded: session 10 itself says
  fruit "sits on a shorter, less uniform clock, set by ripeness rather than
  a fixed rule," so giving it a fixed calculator duration would contradict
  the course's own stated position.
