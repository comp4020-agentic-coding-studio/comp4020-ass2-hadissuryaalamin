# Task 019 — Spec tests round 2

**Status: completed**

## What was done

Added tests 6-10 to the existing `spec/course-promises.test.ts`, in a new
`describe("course promises — round 2", ...)` block (round 1's file/pattern,
not a separate file — matches its convention of "your own file alongside the
supplied `data-integrity.test.ts`"). No content, deck or component files
touched.

- **Test 6** — twelve lecture entries exist, weeks 1-12, no gaps/duplicates.
  Same pattern as round 1's existing sessions-week test, filtered to
  `type === "lectures"`.
- **Test 7** — every lecture's `meta.slides` (a site path like
  `/decks/week-02/`) resolves to a deck that actually built. Inspected
  `dist/decks/` after a fresh `pnpm build` first: each deck is a static route
  at `dist/decks/week-0N/index.html`, so the assertion strips the leading/
  trailing slashes off `slides` and calls `existsSync` on
  `dist/<deckDir>/index.html`, rather than assuming a shape.
- **Test 8** — checked `dist/api/index.json` directly first: the `sessions`
  schema's `.loose()` `tutorial` field does surface, as `meta.tutorial`
  (boolean) on each sessions node — same place `week`/`date` already live.
  Asserts exactly seven `tutorial: true` (weeks 2,3,4,5,8,9,10) and five
  `tutorial: false` (weeks 1,6,7,11,12).
- **Test 9** — nutrition citation for weeks 2, 3, 4, 9. Investigated the
  built API before writing this one: `links: []` (the `label`/`url` pairs
  from frontmatter) is **not** included in the aggregate
  `dist/api/index.json` — traced to `astro-course-university`'s
  `generateIndexJson`, whose `IndexEntry` type deliberately omits `links`
  (only `id/type/title/description/tags/related/spec/meta`). `links` only
  appears on each node's own per-node file,
  `dist/api/<type>/<slug>.json` (via `generateNodeJson`). So this test reads
  that per-node file (a small `loadNode(id)` helper added to the test file)
  and asserts at least one `links[]` entry's `label` or `url` matches
  `/FoodData Central/i` for each of the four lectures. Confirmed present by
  inspecting `dist/api/lectures/week-0{2,3,4,9}.json` directly.
- **Test 10** — storage-safety citation for weeks 5, 8, 10. Checked both
  candidate locations before writing the assertion: `dist/api/lectures/
  week-05.json` has no USDA/FSIS link (only aromatic-chemistry sources), and
  `week-08.json` has no `links` at all — the citation for both actually
  lives on the **tutorial (sessions) page** instead
  (`dist/api/sessions/05-aromatics-and-oil.json` and
  `.../08-timed-mise-en-place.json`, both citing USDA FSIS "Danger Zone" /
  "Leftovers and Food Safety"); week 10 carries it on both its lecture and
  session. Adapted the assertion accordingly: for each of weeks 5/8/10 it
  collects every lecture-or-session node for that week and requires *at
  least one* of them to carry a link matching `/USDA|FSIS|FoodSafety\.gov/i`,
  rather than hard-coding "must be on the lecture" as the task file's
  phrasing assumed.
