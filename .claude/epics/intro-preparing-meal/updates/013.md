# 013 — Macro/calorie calculator

Status: completed.

## What was built

- `src/data/macro/types.ts` — shared `MacroSource` / `MacroIngredient` /
  `MacroWeekData` types. One data file per week, each a default export of a
  `MacroWeekData` object: `{ week, title, source, ingredients[] }`. Each
  ingredient carries `name`, `fdcId`, `fatPer100g`, `proteinPer100g`,
  `caloriesPer100g` — all per 100 g of the raw, edible portion.
- `src/data/macro/week-02.ts` (Vegetables), `week-03.ts` (Poultry and fish),
  `week-04.ts` (Red meat), `week-09.ts` (Fruit) — one file per week named in
  epic.md Round 2 constraint 12.
- `src/components/MacroCalculator.astro` — the reusable calculator.

## Data sourcing

All figures are from USDA FoodData Central (https://fdc.nal.usda.gov/),
SR Legacy entries. Each figure was checked via web search against at least
one independent secondary source citing the same FDC ID before being
recorded, since the FDC site itself is a JS-rendered SPA that this session's
fetch tool could not load directly (returns 404 to non-browser requests —
the deep-link URL format is still correct and resolves for a human in a
browser). The FDC ID is stored on every ingredient and is what the
component's citation link points at, so a marker can verify the exact entry.

## Component design

`src/components/MacroCalculator.astro` — no client framework is configured
in `astro.config.ts` (theme + course-graph + astromotion only), so the
interactive part is plain vanilla JS in a `<script>` tag, following Astro's
recommended pattern of querying `.macro-calculator` by class and looping
`querySelectorAll(...).forEach(...)` so the (deduplicated) script handles
any number of instances on one page.

Props:
- `data: MacroWeekData` (required) — one week's data file.
- `headingLevel?: "h2" | "h3" | "h4"` (default `"h2"`) — so it nests under
  whatever heading level the embedding tutorial page is at.
- `defaultGrams?: number` (default `100`) — initial quantity; the first
  render's output (fat/protein/kcal for the first ingredient at this many
  grams) is computed server-side in the component's frontmatter, so the
  calculator shows a correct, non-blank result before any JS runs.

Behaviour: a labelled `<select>` of ingredients (options carry the per-100 g
figures and FDC ID as `data-*` attributes) and a labelled numeric grams
`<input>`. On `change`/`input`, a script recomputes
`figure_per_100g * grams / 100` for fat, protein and calories, and rewrites
the citation link's text and `href` to point at the selected ingredient's
own FDC permalink (`https://fdc.nal.usda.gov/food-details/<fdcId>/nutrients`).
All native form controls — fully keyboard-operable, visible
`:focus-visible` outline via `var(--at-accent)`, no colour-only state.
Styling uses only the theme's existing `--at-*` design tokens (spacing,
colour, radius, font-size) from `astro-theme-university/styles/tokens.css`,
so it matches the rest of the site without a new stylesheet or dependency.
